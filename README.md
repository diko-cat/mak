# Клиника «Сана» — демо-приложение

Frontend на Vite, React, TypeScript и Tailwind CSS. Данные API сейчас хранятся в `localStorage`; UI использует async-функции из `src/api`, поэтому mock-слой можно заменить сетевым клиентом без смены вызовов в компонентах.

## Запуск

```bash
npm install
npm run dev
```

Production-сборка: `npm run build`; локальный просмотр сборки: `npm run preview`.

## Демо-доступ

На странице входа роль выбирается карточкой, после выбора email и пароль заполняются автоматически.

| Роль | Email | Пароль |
| --- | --- | --- |
| Пациент | `patient@sana.demo` | `SanaPatient2026` |
| Врач | `doctor@sana.demo` | `SanaDoctor2026` |
| Администратор | `admin@sana.demo` | `SanaAdmin2026` |

## API mock-слой

Типы сущностей и ошибок находятся в `src/types`; async API-контракт — в `src/api/index.ts`; демо-база и её начальные данные — в `src/api/database.ts`.

Контракт включает данные клиники, врачей, услуг и пациентов; вход и демо-реквизиты; чтение, создание и смену статуса записей; свободные слоты; медицинские заключения; анализы; заявки на обратный звонок. Запись проверяет прошедшее время и пересечение с уже занятым интервалом врача. Гостевые заявки сохраняются в `localStorage`.

## Роуты

- `/` — публичная страница клиники.
- `/login` — вход и выбор демо-роли.
- `/patient` — кабинет пациента: обзор с талоном ближайшего приёма, последним заключением и анализами с отклонениями.
- `/patient/appointments/new` — запись: услуга → врач (активный, нужной специальности) → дата (7 дней) → время → причина.
- `/patient/appointments` — мои записи (запланированные, завершённые, отменённые), отмена с подтверждением.
- `/patient/results` — заключения врачей и анализы, значения вне нормы помечены.
- `/doctor` — расписание врача на сегодня/завтра/послезавтра, карточка приёма, заключение и «Завершить приём».
- `/doctor/patients` — пациенты врача: число визитов, ближайший визит, история заключений.
- `/admin` — обзор: записи и выручка за сегодня, загрузка врачей по их рабочим часам, заявки на звонок, ближайшие приёмы.
- `/admin/appointments` — все записи: поиск, фильтры по врачу, дате и статусу; подтвердить, перенести (выбор врача той же специальности, даты и свободного слота), отменить с подтверждением.
- `/admin/doctors` — врачи: добавить, изменить, закрыть/открыть запись, удалить (только если у врача нет записей).
- `/admin/schedule` — рабочие часы врача по дням недели и нерабочие даты; после сохранения показываются приёмы, выпавшие из графика.
- `/admin/services` — услуги и цены: быстрая правка цены в списке, добавление, редактирование, удаление.
- `/admin/access` — матрица прав по ролям.

## Права ролей

Права описаны в `src/auth/permissions.ts` и проверяются в API (`requirePermission`), а не только в интерфейсе:

- **Пациент** — записаться от своего имени, видеть и отменять свои записи, видеть свои заключения и анализы.
- **Врач** — видеть свои приёмы и пациентов, завершать свой приём с заключением.
- **Администратор** — все записи (подтверждение, перенос, отмена), врачи, услуги и цены, рабочие часы и расписание, заявки на звонок.

Слоты записи строятся по рабочим часам врача (`src/api/schedule.ts`); в выходной и в нерабочую дату слотов нет. Демо-база — `sana-clinic.database.v3` (при обновлении данные пересоздаются из начального набора).

Кабинеты лежат в `src/pages/patient` и `src/pages/doctor`, общие для них стили и форматирование — в `src/pages/cabinet`.

Тема и сессия также сохраняются в `localStorage`.
